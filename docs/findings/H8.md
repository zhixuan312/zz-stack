# H8 — the block name in `zz.decision` was written seventeen ways for three blocks

`zz.decision.blocks` is the column answering "what have we predicted about casebox". It is GIN-indexed
so that question is one query, and `reconcile` — the join that puts a prediction next to what
actually happened — matches it against the block name the gateway records on each call.

The gateway's name is always the bare one: `casebox`. The decision's name was whatever the author had
typed on a free-text `server:` line, and across the corpus that was:

    casebox:         casebox, ops_casebox, mcp_casebox, mcp-casebox, mcp__plugin_ops_casebox, mcp__plugin_ops_casebox__*
    RuleMill:       RuleMill, ops_rulemill, mcp-RuleMill, mcp__plugin_ops_rulemill, RuleMill"
    bookit:  bookit, ops_bookit, mcp_bookit, "bookit
    neither:    +, MCP

Seventeen values, three blocks, and two entries that are not blocks at all. `casebox` was spelled six
ways across 379 rows, of which 116 matched what the gateway writes.

So `reconcile` was joining on about a third of the rows it should have and reporting the rest as
predictions about nothing — silently, since a join that finds no partner produces no error, just
a smaller answer. Every "prediction versus reality" number produced before this is understated by
an unknown amount, and the honest thing to do with them is discard them rather than scale them.

A client prefix is not part of a block's identity. `mcp__plugin_ops_casebox__get_cases` is casebox seen
through one client's naming convention, and a record that keeps the client's spelling is a record
that changes meaning when somebody swaps clients.

## Fixed at the point of writing, and one near-miss worth keeping

Names are now normalised as they are indexed: lowercased, quotes and stars stripped, the client
wrappers peeled longest-first (`mcp__plugin_ops_` before `mcp_`), and what remains kept only if it
still looks like a name.

The first version of that rule filtered to tokens longer than two characters, which deleted the
shortest block id on the deployment entirely — the most-used one — while leaving the longer names
looking perfectly correct. It was caught by running the rule over every spelling the store actually
holds instead of over the spellings I had in mind while writing it. That is the only reason it
was caught, and it is now how the rule is tested.

Not backfilled, per the standing instruction that only future data matters.
