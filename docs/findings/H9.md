# H9 — the second version resumes the first version's work, so A/B comparison is invalid

ops-intent 1.1 was measured against 1.0 on eight held-out requirements. Three produced no document
at all, and the reported delta was 0.000 across the five that did. Both numbers are artefacts.

r05's own transcript says what happened: it called `initiative_status`, found
`2026-08-30-onboarding-checklist/intent.md` — the initiative the 1.0 run had created the day
before — and resumed it rather than starting a duplicate. It was RIGHT to. ops-intent says a
folder that already exists "is almost certainly the same work: check S0's resume question", and
zz-backbone requires the status call before continuing anything. The skill obeyed both.

The defect is in the harness, which re-runs one corpus into a store that still holds the previous
version's output. Two consequences, and the second is worse than the first:

1. Requirements whose earlier initiative is found produce nothing, silently shrinking the sample.
   Eight became five, and nothing in the run log said so — the runner reports a completed turn.

2. The requirements that DO write are writing while able to read the previous version's document.
   That is not version 1.1 answering a requirement; it is 1.1 revising 1.0's answer. The measured
   delta is contaminated in the direction that flatters continuity, and no amount of re-reading
   the numbers separates the two.

So: ops-intent 1.1 is UNTESTED. Not "no better" — untested. Reporting 0.000 as a result would have
been the same error as the too-good scores this whole exercise started from, arrived at from the
other side.

## What a valid comparison needs

Each version runs against a store that holds nothing from the other. Either reset between
versions, or give each version its own namespace so a resume can never cross the boundary.

## The larger gap this exposed, which no reset fixes

There is no variance estimate anywhere in this apparatus. Every requirement has been run ONCE per
version, so a per-requirement delta of +0.40 cannot be told apart from the same requirement run
twice at the same version. On the held-out five the deltas were +1.60 and -1.20 in the same set —
a spread that says loudly that single runs are not measurements.

Until the same requirement is run several times at ONE version and the spread of that written
down, no delta produced here can be called an improvement or a regression. That is the next rung,
and it comes before any further skill changes are ranked, because ranking noise produces a
confident ordering of nothing.
